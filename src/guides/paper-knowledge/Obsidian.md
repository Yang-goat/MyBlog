# Obsidian：搭建本地科研知识库

对于长期读论文、做实验、写项目记录的人来说，只把 PDF、代码、截图和零散想法放在文件夹里并不够。真正需要积累的是：读完一篇资料后的判断、某个概念和项目之间的关系、实验失败的原因，以及下一步该做什么。

Obsidian 适合承担“知识加工”的部分。它把笔记保存在本地 Markdown 文件中，又提供双链、反向链接、图谱、Properties 和 Bases 等功能，可以把论文理解、概念、项目和实验记录连接起来。

> 本文写作与验证时间为 **2026-07-06**。Obsidian 的界面、核心插件和功能名称可能更新，实际以官方文档为准。

## 适合什么场景

这个配置适合：

- 需要长期整理课程、论文、实验和项目资料；
- 希望笔记保存在本地 Markdown 文件中；
- 想用双链把概念、论文、项目和实验记录串起来；
- 想用 Properties 和 Bases 管理阅读、实验和项目状态；
- 不想一开始安装大量社区插件。

不太适合：

- 只想临时写几条零散备忘；
- 更依赖团队实时协同编辑；
- 希望工具自动完成知识整理；
- 不愿意维护笔记命名、状态和链接关系。

::: important 核心原则
Obsidian 不应该只是“资料仓库”。它更适合保存你自己的理解、判断、问题和下一步行动。
:::

## 安装与新建 Vault

打开 Obsidian 官方下载页面，下载对应系统的桌面版安装包。第一次启动后选择：

```text
Create new vault
```

Vault 可以理解为一个本地笔记库，本质上是一个普通文件夹。Obsidian 的核心内容保存在本地 Markdown 文件中，即使以后不用 Obsidian，也可以用 VS Code、Typora 或普通文本编辑器打开。

建议为科研内容单独建立一个 Vault，避免和生活备忘、临时摘抄混在一起。不要把一个 Vault 嵌套在另一个 Vault 里面，否则内部链接和同步更容易混乱。

## 开启必要核心插件

进入：

```text
Settings -> Core plugins
```

建议先开启这些核心插件：

| 插件 | 用途 |
|---|---|
| Backlinks | 查看哪些笔记链接到当前笔记 |
| Outgoing links | 查看当前笔记链接到了哪里 |
| Graph view | 查看笔记之间的关系图 |
| Daily notes | 快速创建当天记录 |
| Search | 在整个 Vault 中检索文本 |
| Canvas | 画论文脉络、算法关系和项目思路 |
| Bases | 基于 Properties 创建表格、列表或卡片视图 |
| File recovery | 保留文件快照，降低误删风险 |

Obsidian 的核心插件由官方维护，其中 Bases 可以基于笔记的 Properties 创建类似数据库的视图，适合管理阅读列表、项目状态和实验记录。

## 核心用法速查

Obsidian 的核心能力可以先按下面这几类理解：

| 用法 | 解决的问题 | 适合科研中的什么场景 |
|---|---|---|
| 文件与附件 | 管理 Markdown、图片、PDF 等本地文件 | 保存读书笔记、实验截图、草稿和附件 |
| 双链 | 在笔记之间建立明确连接 | 把论文、概念、项目和实验串起来 |
| 反向链接与出链 | 查看一篇笔记被谁引用、又引用了谁 | 找到概念来源、项目相关资料和遗漏连接 |
| 搜索与快速切换 | 在 Vault 中快速定位内容 | 找论文名、算法名、实验记录和待办项 |
| 关系图谱 | 从整体或局部查看笔记网络 | 检查知识网络是否断裂、哪些节点是核心概念 |
| Canvas | 在二维画布上组织材料 | 梳理论文脉络、算法流程和项目路线 |
| Properties 与 Bases | 给笔记加结构化字段并做视图 | 管理阅读状态、项目状态和实验记录 |
| 书签与页面预览 | 快速访问常用内容、减少跳转成本 | 固定项目入口、阅读列表、综述草稿 |

一开始不需要把每个功能都配置得很复杂。更稳妥的顺序是：先写清楚笔记，再建立双链；等笔记多起来后，再用图谱、Bases、Canvas 和搜索去整理。

## 理解 Properties

Properties 写在 Markdown 文件顶部，本质是 YAML frontmatter。它适合保存短小、结构化的信息，例如：

```md
---
type: literature
status: reading
year: 2026
project:
tags:
  - paper
---
```

Properties 适合做筛选、排序和视图管理，不适合承载长段总结。论文方法、个人理解、问题和后续行动应该写在正文里。

常用字段可以保持少量、稳定：

| 字段 | 用途 |
|---|---|
| `type` | 笔记类型，例如 `daily`、`literature`、`concept`、`project`、`experiment` |
| `date` | 记录日期 |
| `status` | 状态，例如 `unread`、`reading`、`done`、`active` |
| `project` | 所属项目 |
| `tags` | 标签 |
| `year` | 论文或资料年份 |

::: tip
字段越少越容易长期维护。先保留能用于检索和排序的字段，后续确实需要时再增加。
:::

## 用双链建立知识网络

Obsidian 最重要的语法是双链：

```md
[[某个概念]]
[[某篇论文]]
[[某个项目]]
```

也可以使用别名：

```md
[[Particle Swarm Optimization|PSO]]
```

建议采用“先链接，后补全”的方式。读资料时遇到重要概念，即使还没写对应笔记，也可以先写出双链。以后再点击这些空链接补充内容。

::: tip 双链优先于标签
具体知识点、算法名、项目名建议用 `[[双链]]`；标签更适合表示状态或宽泛类别，例如 `#paper`、`#experiment`、`#todo`。
:::

## 用反向链接和出链补关系

双链写进去以后，还要定期检查连接是否真正有用。这里主要看两个面板：

| 面板 | 含义 | 适合检查什么 |
|---|---|---|
| Backlinks | 哪些笔记链接到了当前笔记 | 一个概念被哪些论文、项目或实验用到 |
| Outgoing links | 当前笔记链接到了哪些笔记 | 一篇论文是否连接到了相关概念、项目和实验 |

Backlinks 里还可以看到未链接提及。如果某个笔记中出现了一个概念名，但还没有写成 `[[双链]]`，可以用未链接提及把它补成正式连接。

一个实用做法是：写完一篇论文笔记后，打开 Backlinks 和 Outgoing links，检查它是否至少连接到相关项目、2 到 3 个核心概念，以及可能延伸的实验记录。没有连接的论文笔记，后面写综述时很容易被遗忘。

## 用关系图谱检查知识网络

Graph view 是 Obsidian 的核心插件，用来可视化 Vault 中笔记之间的连接关系。图谱里的圆点代表笔记，线代表内部链接。圆点越集中，通常说明它和更多笔记发生了连接。

关系图谱有两种常用视角：

| 图谱 | 作用 |
|---|---|
| 全局图谱 | 查看整个 Vault 的连接结构 |
| 局部图谱 | 只查看当前笔记附近的连接 |

全局图谱适合阶段性整理知识库。可以重点看：

- 哪些笔记完全孤立，没有和任何内容连接；
- 哪些概念是很多论文共同指向的核心节点；
- 哪些项目和实验记录没有连接到论文来源；
- 哪些标签、附件或临时文件干扰了知识图谱。

局部图谱适合读论文和写项目时使用。打开一篇论文笔记的局部图谱，可以快速看到它连到了哪些概念、项目和实验；打开一个项目笔记的局部图谱，可以看到支撑这个项目的资料和问题是否足够完整。

图谱设置里可以用过滤条件减少干扰。例如不想显示图片、附件或某类临时文件，可以在 Graph view 的设置中关闭 Attachments，或者用搜索条件过滤节点。也可以用 Groups 给不同类型的笔记设置颜色，例如让论文、概念、项目和实验呈现不同颜色。

::: warning 不要迷信图谱
关系图谱只能说明“笔记之间存在链接”，不能说明你的理解已经完整。图谱的价值在于发现孤立笔记、核心节点和遗漏连接，而不是追求复杂好看的形状。
:::

## 用搜索、快速切换和书签找资料

当 Vault 变大后，靠文件夹逐层点开会很慢。建议养成三个习惯：

| 功能 | 用法 |
|---|---|
| Search | 搜索正文、标题、标签和字段，适合找关键词 |
| Quick switcher | 通过文件名快速打开笔记，适合跳转到已知页面 |
| Bookmarks | 固定常用项目、阅读列表、综述草稿和重要搜索 |

科研笔记里经常会出现同一个算法名、数据集名或实验指标。搜索适合找所有出现位置；Quick switcher 适合直接打开某篇已知笔记；Bookmarks 适合把当前阶段最常用的入口固定下来。

## 用 Canvas 梳理项目和论文脉络

Canvas 是 Obsidian 的核心插件，适合把笔记、附件和网页放在一个二维画布里，再用连线表达关系。

科研场景中可以用 Canvas 做三类事情：

- 画一组论文之间的继承、改进和对比关系；
- 画一个算法从输入、模型、优化到输出的流程；
- 画一个课题从研究问题、相关工作、实验设计到论文草稿的路线。

Canvas 更适合“思考关系”，不适合替代正式笔记。重要结论仍然建议写回 Markdown 笔记里，否则后续搜索、链接和引用会变弱。

## 常见笔记类型

不需要一开始设计很复杂的系统。科研知识库里常见的笔记可以先分成几类：

| 类型 | 重点 |
|---|---|
| 每日记录 | 今天推进了什么、卡在哪里、明天继续做什么 |
| 论文笔记 | 论文解决的问题、方法核心、实验设计、可借鉴之处 |
| 概念笔记 | 一个术语、算法、模型或评价指标的理解 |
| 项目笔记 | 一个课题或代码项目的总入口，链接相关资料和实验 |
| 实验记录 | 实验目的、参数、结果、异常现象和下一步 |
| 想法记录 | 临时灵感、问题、假设和可能的创新点 |

这些类型不是为了分类好看，而是为了让笔记服务后续工作。写综述时能找到相关论文和概念，做实验时能追溯参数和现象，写论文时能回到项目记录中整理主线。

## 用 Bases 管理状态

Bases 可以把符合条件的笔记展示成表格、列表或卡片。适合先做三个视图：

| Base | 筛选思路 | 用途 |
|---|---|---|
| 阅读列表 | `type` 为 `literature` | 查看哪些资料未读、在读或已总结 |
| 项目列表 | `type` 为 `project` | 查看当前课题和项目状态 |
| 实验列表 | `type` 为 `experiment` | 查看实验是否完成、是否需要复跑 |

阅读列表可以显示：

```text
file
title
year
status
project
tags
```

实验列表可以显示：

```text
file
date
project
method
status
result
next_action
```

这样可以快速回答几个问题：

- 哪些资料还没读？
- 哪些论文已经写过总结？
- 哪个项目目前还在推进？
- 哪些实验需要补参数、补图或重新运行？

## 和 Zotero 的边界

Obsidian 不适合替代 Zotero。

更稳定的分工是：

| 工具 | 负责内容 |
|---|---|
| Zotero | 文献条目、PDF、元数据、引用格式、参考文献导出 |
| Obsidian | 个人理解、概念连接、项目脉络、实验记录、阶段总结 |

也就是说，论文原始文件和引用管理放在 Zotero；读完之后形成的理解、问题、启发和项目连接放进 Obsidian。

如果想把 Zotero 的论文、批注和 Obsidian 笔记串起来，可以继续看：[Obsidian + Zotero + Codex：AI 辅助科研工作流](./ai-research-workflow.md)。

## 推荐的每日使用习惯

一个稳定的使用流程是：

1. 开始工作前写下今天要推进的事项；
2. 读资料时记录核心问题、方法和启发；
3. 遇到重要概念时建立双链；
4. 做实验时记录参数、结果和异常；
5. 产生想法时先保存，不急着判断价值；
6. 阶段性回到项目笔记，把分散内容整理成主线。

长期坚持后，Obsidian 中会自然形成这样的关系：

```text
每日记录 -> 项目笔记 -> 论文笔记 -> 概念笔记 -> 实验记录 -> 想法记录
```

真正有价值的不是“存了多少资料”，而是你能否快速回答：

- 我读过哪些相关工作？
- 它们解决了什么问题？
- 有哪些方法可以借鉴？
- 我的实验记录在哪里？
- 我的想法来自哪些资料和现象？

## 常见问题

### Properties 里可以写长总结吗？

不建议。Properties 适合写短字段，例如 `status`、`year`、`project`。总结、方法分析和个人理解应该写在正文中。

### Bases 会不会锁死数据？

不会。Bases 只是读取 Markdown 文件和 Properties，并把它们展示成视图。笔记内容仍然保存在本地 `.md` 文件中。

### 一开始需要装很多社区插件吗？

不需要。先把核心插件、双链、Properties 和 Bases 用起来。后续确实需要时，再考虑安装社区插件。

### 笔记标题用中文还是英文？

都可以。概念和算法名建议使用稳定名称，例如 `NSGA-II`、`Pareto Front`、`Particle Swarm Optimization`。项目和每日记录可以用中文，关键是保持命名一致。

## 建议先完成的最小闭环

不要一开始追求完整系统。建议先完成这个最小闭环：

1. 新建一条当天记录，写今天计划；
2. 整理一篇论文或资料；
3. 从论文笔记链接 2 到 3 个概念；
4. 新建一个项目笔记，把相关资料和概念链接进去；
5. 做一次实验后，记录参数、结果和下一步；
6. 回到当天记录，写清楚今天推进了什么、明天继续做什么。

只要这个流程能跑通，Obsidian 就已经可以发挥作用。后面再逐步加入更多视图和自动化。
