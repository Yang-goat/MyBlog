# 论文随笔：从论文到可读的分享

目标是让有相关基础、尚未读过原文的读者理解：问题在哪里，方法改变了什么，证据支持到哪里，以及为什么值得继续读。根据读者背景调整深度，不逐节翻译论文，不把摘要扩写成全文。

## 先读来源，再确定主线

- 核对标题、作者、年份、发表来源、DOI 或稳定原文链接；区分预印本版本与正式发表版本。代码、项目页和补充材料在实际使用时链接。
- 写完整解读前阅读原文相关方法、实验和局限部分，不能只凭摘要、搜索摘要或他人解读补齐细节。只有摘要可用时，明确写成有限范围的介绍；无法核实的关键内容向用户索取原文，不编造完整精读。
- 起草时将核心主张对应到章节、公式、图表或页码，同时记下成立条件。这个对应关系用于核对，不必把内部记录整表放进博客。
- 选择一个中心问题，找出相对已有方法真正发生变化的环节。背景只补到能解释这个变化；涉及继承、首次提出或优于某方法时核对原始来源。

## 单篇分享的推荐叙事

以下是内容顺序，不是必须照抄的标题；篇幅由理解难点决定。

1. **用问题开篇**：给一个具体困难或场景，说明为什么选这篇，以及最值得带走的观点。紧接简短论文信息和原文入口，不以大表格或长摘要挡住正文。
2. **交代已有方法卡在哪里**：说明任务、输入输出、目标和必要假设；只引入后文会用到的背景。
3. **讲清核心办法**：先用一段话概括，再沿数据流、算法步骤或推理链拆解。每个关键机制说明“做什么、为何这样做、相对基线变了什么”。用一个贯穿的小例子或示意图帮助理解；不要求每篇都有图。
4. **用证据回答是否有效**：挑与中心主张最相关的结果，交代测试对象、指标方向、基线和预算等影响比较的条件，定位原文图表。解释结果意味着什么，而非抄满整张表。
5. **给出边界与自己的理解**：分清原文承认的局限、自己从证据提出的疑问，以及对自己问题的潜在启发。没有实际复现时不写“我验证了”。结尾可给适合继续阅读的人和下一篇关联。
6. **列出实际使用的参考资料**：正文关键主张附近保留来源定位，文末提供稳定入口。

标题可采用“方法名：它怎样解决具体问题”，避免仅贴英文论文名或使用“全面超越”等无条件结论。第一人称可以表达有依据的理解，不替用户编造动机与经历。

## 按阅读任务调整

| 用户意图 | 应保留的内容 | 可压缩或另文承接的内容 |
| --- | --- | --- |
| 分享一篇论文 | 核心问题、机制直觉、关键证据、适用边界 | 完整推导、全部实验与实现细节 |
| 深入精读 | 上述内容，加关键推导、算法细节、实验设计与尚未解决的问题 | 与中心问题无关的背景 |
| 多篇对比或周记 | 围绕共同问题连接各篇贡献，比较假设与证据，留下后续问题 | 已有精读正文，通过链接引用 |
| 复现记录 | 论文目标、实现版本、环境与预算、自己的结果、差异与排查证据 | 论文介绍可链接原有解读 |

理论论文以命题、假设、证明思路和反例边界作为证据，不硬套实验章节；综述按分类视角、覆盖范围与遗漏组织，不虚构统一的“新算法”。

周记不是论文清单。先交代本周共同问题，再说明各篇如何补充或冲突；只比较条件可比的结果。没有阅读日期或周次时不要自行编造。

## 证据与表达的边界

- 使用“作者在……设置下报告”“这可以理解为……”“本次复现得到……”等自然表达区分证据来源，无须给每段加机械标签。
- 实验数字核对单位、指标方向、数据划分、预算、基线版本及统计口径。相对提升与百分点不同；没有独立重复或显著性证据，不写“显著优于”。
- 消融支持特定设置下某组件的贡献，不自动证明全部机制解释；单个基准上的优势不外推为普遍优势。排名和奖项另查官方结果。
- 论文、作者代码与后续实现可能不同；明确采用哪个版本，不把实现细节反写成论文原文。
- 图表说明来源与图号，注明转载、改绘或自行示意。重绘保持坐标、单位和比较条件；示意图不伪装成实验结果。外部图片依许可使用。
- 算法公式解释变量与更新顺序。省略推导时说明省略范围，不能略去决定结论成立的条件。

## 本站落点与交付前检查

按 [内容结构](../../../../docs/content-structure.md) 选择专题目录；`paper-notes/weekly/` 保存周记。用户说“论文随笔”并不自动等于周记，也不自动要求新增栏目。同一精读只维护一份正文，周记与专题通过正文链接关联。

交付前从陌生读者角度通读：能否说出问题、关键改变和证据边界？例子是否真正解释了难点？再按原文复核关键机制、数字、图号、书目信息和个人判断的归属。仓库构建与链接检查按主 Skill 执行。

## 写法参考

以下来源用于借鉴表达方法，不是未来每篇论文随笔都要引用的文献；本次查阅于 2026-09-20。

- [BAIR：LLM-grounded Diffusion](https://bair.berkeley.edu/blog/2023/05/23/lmd/)：从具体失败场景进入研究问题，再解释方法与展示结果。
- [Olah：Understanding LSTM Networks](https://colah.github.io/posts/2015-08-Understanding-LSTMs/)：先讲直觉，再用连贯图示逐步拆解机制。借鉴讲法，技术结论仍核对原始论文及版本。
- [Distill：Research Debt](https://distill.pub/2017/research-debt/)：重视整合与解释已有知识，减少读者理解研究所需的重复劳动。
