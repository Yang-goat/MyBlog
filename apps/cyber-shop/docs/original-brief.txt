Phaser 是游戏子项目的正式依赖：
- 声明在游戏的 package.json。
- 由仓库现有 pnpm workspace 管理。
- 正常更新锁文件。
- 不全局安装 Phaser。
- 不直接修改 node_modules。
- 不为此升级或替换整站无关依赖。
- 访客不需要安装 Phaser，发布时随游戏一起打包。
单一游戏状态
Vue 和 Phaser 必须共用同一套权威游戏状态。

推荐结构：
apps/cyber-shop/
├── src/
│   ├── game/          # 纯规则、状态、动作、随机数和结算
│   ├── content/       # 商品、人物、技能、证书、事件、任务
│   ├── scenes/        # Phaser 场景
│   ├── ui/            # Vue 界面
│   ├── persistence/   # 存档、导入导出、版本处理
│   └── assets/        # 参与构建的资源
├── public/art/        # 游戏美术
├── tests/
├── scripts/
└── progress.md
规则层通过统一动作入口处理：
applyAction(state, action) → 新状态与表现事件
例如检查、报价、成交、维修、交付、陈列、加点和闭店。
- Phaser 和 Vue 负责发送动作、展示结果。
- 动画不能直接决定钱款、物品归属或任务奖励。
- 避免两套库存、两套现金或各自独立保存。
- 高频动画状态不要逐帧写入 Vue 响应式经营状态。
- 弹窗打开时正确屏蔽底层场景点击。
- 热更新、场景切换和退出时清理事件、声音及重复实例。
首版不需要后端、账户、多人联机、在线 AI 对话或 PWA 缓存。

交易循环
每件适用商品可以走通：

查看信息 → 按需检查 → 议价 → 买入 → 入库／加工／陈列 → 匹配买家 → 卖出。
- 买卖双方有不同需求、报价和耐心。
- 议价轮数有限，客户提供可理解的反馈。
- 真伪、故障和底价在生成时确定。
- 刷新不会重新抽取商品或客户底价。
- 每笔交易记录真实成本，防止翻新、回收或退款形成无成本套利。
- 支持拒绝交易、临期清货、库存整理和明确的资金不足提示。

5. 修复师、证书与技能成长
维修操作
维修包含完整流程：

客户描述 → 检测 → 判断故障 → 选择操作与耗材 → 修复 → 复检 → 交付。

基础操作包括：
- 清洁和恢复接点。
- 选择并替换故障模块。
- 根据读数完成参数校准。
通过 12 种故障模板及组合形成不同维修案例。高阶维修增加判断和工序组合，不要求快速反应。
- 错误操作消耗额外工时或材料，并给出具体反馈。
- 不通过不可解释的随机失败摧毁客户物品。
- 熟练处理重复故障后开放快捷工序，仍消耗正常成本。
- 自有旧货可修复后出售或陈列。
- 客户送修物不能出售、拆解套现或陈列。
- 客户材料预付款专款专用，不能作为自由现金。
- 零现金玩家仍能接受基础维修委托。
维修证书
等级	主要范围	所处阶段
民用电子	通讯器、终端等基础设备	开局
工业设备	工业机电、部分能源设备	主线前中期
神经接口	神经及精密医疗设备	主线中后期
古董科技	古董电子、机械收藏品	通关后


证书通过案例积累、培训和实际考核取得。
- 考核使用真实维修流程。
- 通过后提供对应基础工具。
- 考核失败可以重试，不反复收取培训费。
- 证书扩大维修品类。
- 通用经营许可决定受管制商品的交易资格，两者不能混用。
技能点原则
- 通用树和职业树共用技能点。
- 主线正常节奏下，点数不足以点满所有技能。
- 通关需要集中投入一条专精，取得大师能力。
- 技能点没有全局总量上限。
- 无尽模式继续通过经验和委托获得点数，最终可点满当前版本全部技能。
- 后续新增职业沿用同一成长机制。
首版技能树：24 个实际有效节点
通用技能 12 个，四条分支：
分支	三阶段能力
交易	行情判断 → 议价技巧 → 熟客成交优势
货源	供货预告 → 批次信息 → 定向采购
经营	库存规划 → 保存效率 → 快捷整理与补货
收藏	藏品编目 → 展示组合 → 定向吸引藏家


维修技能 12 个，三条分支：
分支	四阶段能力
精准维修	故障定位 → 安全复测 → 精密校准 → 精修大师
效率工坊	耗材管理 → 快拆装配 → 标准工序 → 工坊大师
翻新收藏	残值判断 → 部件回收 → 品相复原 → 再造大师


形成三种可玩的加点方向：
1. 精准接单：处理高难维修，获取高级委托。
2. 效率工坊：提升单位工时收益，减少重复操作。
3. 翻新收藏：利用收购判断与修复能力获利、积累珍品。
试玩初值：
- 普通节点消耗 1 点。
- 大师节点消耗 2 点。
- 大师节点要求完成分支前置，并已在维修树投入至少 6 点。
- 主线正常节奏预计取得约 10–12 点。
- 取得大师能力至少累计投入 8 点，因此仍需考虑通用技能的取舍。
这些是初值，允许在试玩后调整。
技能重配
- 闭店且没有进行中的专精工单时可重配。
- 首次提供一次免费重配，之后付费。
- 重配预览清楚列出失去和获得的能力。
- 返还点数与扣费一次性结算。
- 保留证书、任务历史、收藏和已完成结局。
- 当前技能提供的加成和动作资格按新配置重新计算。
- 容量降低不删除物品，超容量时限制继续入库。
- 不允许通过重配重复领取永久奖励。

最终委托应是多阶段综合案例，例如街区联络中枢的机电、供能和神经接口修复，允许不同维修加点路线发挥优势。

- 支持恢复当日开始备份或重新开局。

7. 收藏展示柜与无尽模式
收藏展示柜
展示柜初始 3 格，可以升级至 6 格。
- 展示品必须是玩家自有、已鉴定的真实物品实例。
- 放入展示柜后停止普通售卖。
- 撤展后可重新进入交易。
- 支持拖放、点击换展、藏品说明和图鉴。
- 每件物品只能处于一个位置，不能同时出现在展柜和货架。
- 客户送修物不能陈列。
吸引力综合：
- 稀有度。
- 保存或修复状态。
- 来源与收藏意义。
- 品类搭配与主题组合。
同款重复展示收益递减。吸引力影响客户类型、高端订单和购买意愿，不直接等同于物品价格，也不无限增加每天的操作量。

普通特殊商品同样可以收藏，不局限于古董。
古董修复
古董可同时具有功能状态和原貌价值。
- 并非所有古董都适合恢复成“全新”。
- 更换原始部件可能改善功能，但降低原貌价值。
- 委托明确说明客户希望恢复功能还是保存原貌。
- 修复师负责技术修复；未来策展人负责深度考据、展览和拍卖。
通关后的循环
发现珍品 → 收购或接取委托 → 修复与鉴定 → 展示或出售 → 吸引新客户 → 获得更高阶机会。

通关后：
- 永久免租。
- 保留全部资产、证书、技能、人物关系和收藏。
- 胜利界面可选择结束并保存结局，或继续经营。
- 古董商、收藏家、高级送修客户通过首次来访事件介绍。
- 解锁古董科技考核与对应维修。
- 持续获得技能点，能够点满本版本技能树。
- 提供主题收藏、珍品订单、批量维修、经营纪录和陈列工程。
无尽数值方向
- 成长主要提高单次交易与服务的价值。
- 收益采用温和曲线，效率加成有边界。
- 基础维护费不随天数无限增长。
- 可选挑战明确展示投入、期限、奖励和失败代价。
- 拒绝挑战不产生额外强制惩罚。
- 失败不撤销经营权，也不没收已有展示藏品。
- 没有现金时依然可通过基础维修恢复。
无尽模式当前验证持续成长与经营闭环，后续再重做具体数值。
8. 美术、界面与操作体验
美术方向
原创写实概念插画，呈现：
- 青色霓虹与暖色工作灯。
- 金属、玻璃、塑料及旧物磨损。
- 有生活气息的赛博朋克街区与杂货铺。
- 清晰的人物和商品轮廓。
- 可以承载文字和交互的画面留白。
游戏视觉以店铺、人物和物品为中心，避免做成大量统计卡片堆叠的后台界面。
素材清单
计划逐项生成 66 项基础素材：
内容	数量
商品	36
人物	10
工具、耗材、设施	16
场景：城市标题、店铺、工作台	3
结局图	1


要求：
- 每个基础对象分别生成和登记。
- 人物、物品优先透明背景。
- 先确定统一风格样本，再逐项扩展。
- 保存资产 ID、提示词、用途和最终文件位置。
- 项目引用的图片必须进入项目目录。
- 文本、数字、价格和按钮由真实界面渲染。
- 状态变体可复用基础素材，不能将简单换色算成新的基础商品。
- 生成失败如实记录并继续处理，不能把主要素材缺失的版本当作美术完成版。
使用当前可用的图像生成工具，不要求访客运行时生成图片。
资源与性能
- 按场景和章节组织加载，避免启动时阻塞下载全部高清原图。
- 转换为合适的发布尺寸和格式，保留透明通道。
- 提供加载进度、资源失败提示和重试。
- 校验资源大小写与路径，避免 Windows 可用、GitHub Pages 缺图。
- 动效集中用于客户到访、工具操作、维修成功、交易和藏品入柜。
- 音效提供静音与音量控制。
操作与适配
- 鼠标拖放和点击替代均可完成主要操作。
- 触控不依赖悬浮提示。
- 关键文字与按钮在手机横屏可读、可点击。
- 支持全屏，正常响应 Esc。
- 页面缩放和全屏变化后拖放坐标仍准确。
- Vue 弹窗和 Phaser 场景之间不发生点击穿透。
9. 存档、扩展接口与测试入口
存档
至少保存：
- 存档结构版本、内容与数值版本。
- 随机数状态。
- 营业日、章节与当前阶段。
- 现金、费用及成本记录。
- 商品实例、位置和玩家已知信息。
- 客户、订单与未完成委托。
- 技能点、技能、证书、许可。
- 人物关系和事件进度。
- 展示柜、图鉴与经营纪录。
- 通关及无尽状态。
提供：
- 自动存档。
- 营业日开始备份。
- 继续游戏。
- 导出和导入。
- 损坏或不兼容存档提示。
不能静默覆盖损坏存档。游戏存档命名空间与海克斯麻将完全独立。

本机与正式域名属于不同站点存储，通过导出、导入迁移进度。
扩展接口
至少分离以下概念：
- ItemDefinition：商品模板。
- ItemInstance：具体物品状态与玩家知识。
- CategoryDefinition：分类信息与交易规则。
- ProfessionDefinition：职业能力与胜利里程碑。
- 技能、证书、许可、工具、设施、配方。
- 人物、事件、委托及收藏主题。
新增职业应主要通过注册内容和规则能力接入，不要求重写全部界面。
测试入口
提供：
- window.render_game_to_text()：输出当前玩家可见状态。
- window.advanceTime(ms)：供测试控制表现时间。
- 固定随机种子的开局与规则测试入口。
测试时间推进不能意外增加营业日或产生收益。玩家可见状态输出不泄露尚未鉴定的真实属性。

12. 验收标准与交付物
功能验收
必须实际验证：
- 六类商品都能买入、入库、匹配客户并卖出。
- 分类差异确实影响交易与经营。
- 客户送修、旧货翻新、古董修复完整可用。
- 四级证书与通用许可正确生效。
- 24 个技能节点都有实际效果。
- 主线需要专精；无尽持续获得点数并能点满。
- 重配技能不复制奖励、不删除物品、不破坏任务。
- 展示品不能被普通交易自动卖掉。
- 收藏影响客户、订单或购买意愿。
- 零现金、空库存、满仓、考核失败仍有明确处理方式。
- 刷新、重复点击、导入导出不重复结算。
- 胜利后“结束”和“继续经营”都可用。
规则与浏览器测试
- 使用固定种子测试三种维修加点方向的主线可达性。
- 小批量模拟用于发现死锁、异常数值和套利，不要求最终平衡指标。
- 至少一次通过正常 UI 操作，从新游戏走到胜利并继续无尽。
- 另外验证古董客户、古董修复、陈列和持续获得技能点。
- 不通过直接修改胜利标记来替代完整流程验收。
- 查看实际截图，覆盖 Vue 界面与 Phaser 场景。
- 检查控制台错误、缺失资源、音频解锁、缩放、全屏和触控。
- 自动化快速通关不能证明两小时体验；记录完整流程的内容覆盖和实际试玩耗时。
