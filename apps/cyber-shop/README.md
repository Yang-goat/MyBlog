# 赛博杂货铺

暂停式赛博朋克经营游戏：接待街坊、交易旧货、修复设备、整理收藏，逐步取得永久经营权。首版完整职业为修复师，提供主线结局和无尽经营。价格与成长速度属于试玩配置；约两小时通关是节奏目标。

玩家先看[游戏介绍与操作说明](../../src/notes/cyber-shop/README.md)。开发进展、已执行检查与待办见 [progress.md](progress.md)，最终验收与发布状态以专门的验收记录为准。

## 本机运行

在博客仓库根目录运行。依赖由现有 pnpm workspace 和锁文件管理；首次检出后使用 `pnpm.cmd install --frozen-lockfile` 安装。

| 命令 | 用途 |
| --- | --- |
| `pnpm.cmd cyber:dev` | 开发服务：<http://127.0.0.1:4175/cyber-shop/> |
| `pnpm.cmd cyber:build` | 类型检查并构建游戏 |
| `pnpm.cmd cyber:preview` | 预览已构建游戏：<http://127.0.0.1:4176/cyber-shop/> |
| `pnpm.cmd cyber:validate` | 原有 66 项资源、6 项分层场景素材与内容注册表校验 |
| `pnpm.cmd cyber:test` | 规则、成长、成本与存档测试 |
| `pnpm.cmd cyber:typecheck` | Vue 与 TypeScript 类型检查 |

开发和预览分别在独立终端运行，都启用严格端口检查。停止时在启动服务的终端按 `Ctrl+C`；重新运行相同命令即可重启。端口已占用时先确认现有服务，不重复启动。

游戏构建输出到 `src/.vuepress/dist/cyber-shop/`。整站发布使用 `pnpm.cmd site:build`，按博客、海克斯麻将、赛博杂货铺的顺序构建。完整验证、产物检查与发布分支约束见[项目维护文档](../../docs/maintenance.md)。正式目标路径为 <https://goatyang.com/cyber-shop/>；本机构建结果不代表线上版本已更新。

## 游玩与保存

店铺背景铺满游戏窗口，日期、现金与工时在左上电视显示，库存、成长、采购、收藏、手记和设置入口嵌在右下柜体。主界面从上到下是店外来货、谈判台和自有仓库。新开局和每天开门后，先按右侧设备上的绿色按钮叫号，再交谈，再把来货拖到谈判格子；购买后货物仍留在台面，需要拖入仓库。三个区域均检查占格和重叠，未购买物品不能入库。仓库为 24 列正方形细格，36 类物品按实际形状分别设计占地；Q/E 旋转，点选物品再点空格也可移动，悬停时，指针附近的信息卡显示购入价、估值、预计售价、已知属性与描述；右键打开物品操作菜单。触屏点选会在人物窗口显示详情，长按打开操作菜单。未检查出的属性不会提前揭示。双击可打开详细账目。

卖家每次带来一批货，每件的型号、品相、故障与报价独立生成，检查结果分别保存。交易面板可逐件点选、只买一件或整批放到谈判台；同次购入至少 3 件享九折，分次购入不累计优惠。售出也支持单件或多件分批操作，显示买家剩余预算；超出预算时可“按预算挑选”。结束当前接待后再呼叫下一位；已经买下的商品始终保留在台面。右侧九街通讯显示当天行情，点击可阅读街区事件并选择回应。

没有顾客时也能把自有库存拖到谈判台暂存，腾出格位整理仓库；其他物品保持原位，不会自动补位。谈判台与仓库采用相同的放置预览：绿色表示可放，红色表示重叠、越界或不符合放置条件；旋转后同步更新占格。自有物品不能放到店外来货区。台面摆放随存档保存，取消交易选择也不会把自有物品自动送回仓库。闭店前必须清空谈判台：自有物品全部入库，未购买的来货撤回店外；未清空时不会结算或扣费。

街坊订货簿从库存、任务板和手记打开。十二种需求覆盖六类货品，每日发布三份，同时最多接两份；固定整单货款、明确交期，交货使用半个工时。实际验收按所选自有库存的型号、知识、品相、功能、容量、纯度、完整度、接口、来源与保质期进行。库存成本、交货清单和回信保留，完成数与收入累计；历史保留最近 40 份已结束订货及当前在手和当日来信。超期、取消无罚款，不扣除库存。

仓库“扩容 +”可安装旧式收纳背包（24 格）或堆叠储藏箱（每只 48 格）；新增空间在原有格子下方，滚动可见。已有库存架与技能扩容继续可用。新增格位与物品位置自动保存。新开局包含九步引导，左侧开店笔记可跳过或重读。

工作台完成检测、工序、复检和交付。手动工序包括擦净接点、拆装模块和对齐信号；准备完成后会显示工时、材料与现金成本，再执行实际维修。熟练玩家也可切换参数操作。任务板按实际进度提示四章目标，闭店收据显示现金流、费用及下一步；各经营菜单从右下柜体打开。`F` 切换全屏，`Esc` 关闭面板，设置中可调音量、环境音与减少动态，偏好单独保存。支持电脑与手机横屏。

客户送修件及材料预付款独立保管，展示品退出普通售卖。零现金时可接基础援助维修；首次欠费后仍有三次营业日结可补救，任务板优先显示补缴目标，日结账单标出最后日期与下次应付总额。停业后可恢复当日开门备份。通关需要维修大师能力、职业最终委托与经营权收购款，之后可保存结局或继续免租经营；永久经营权不会因维护欠费被收回。

维修委托页可切换到修复档案，查看最近 80 次交付的收件日、交付日、前后品相、实际工序与报酬。跨日工单和未解决问题的操作都会如实留下记录；早期存档没有的历史不补写。回访对白会根据尚未完成的工单或真实交付记录变化。

每次成功经营操作自动保存，营业日开门时保存恢复备份。命名空间为 `cyber-shop:save:v1` 与 `cyber-shop:day-start:v1`，独立于海克斯麻将。

换设备或在本机与正式域名之间迁移时，先导出当前存档，再到目标环境导入。导出文件只含当前进度，不携带原站点的当日开门副本；导入后以导入点建立本地恢复备份，从下一营业日起恢复按开门状态备份。损坏或版本不兼容的文件会被拒绝；自动保存不会静默覆盖已有损坏存档。

## 代码与扩展入口

Vue 3、TypeScript 与 Vite 使用本仓库工具链。店铺通过 Canvas 2D 分层绘制墙面、窗外、台面与设备，独立图片承载街景、金属纹理、终端和焊台；天气、灯光和车流由表现时间驱动。场景按可见性暂停绘制，限制像素密度并尊重减少动态设置。旧 Phaser 依赖保留在锁文件中，当前运行时代码已不导入它。声音通过 Web Audio 合成，在玩家首次交互后启动。

新增商品或案例先注册内容，再接入规则动作；界面只发送动作并展示结果，不另存一套现金或库存。新职业通过能力、技能和最终里程碑接入共用成长，不永久锁定玩家的开局职业。涉及存档字段变化时显式处理结构、内容与数值版本。

测试可使用固定种子开局。`window.render_game_to_text()` 输出玩家可见状态，`window.advanceTime(ms)` 控制表现时间；推进表现时间不产生收入或新营业日。

六职业总体设计与后续接入方法见[职业设计](docs/professions.md)，内容规模和章节安排见[内容地图](docs/content-map.md)，数值调整与适用范围见[试玩数值记录](docs/balance-notes.md)。合成工匠、能源技师、生态培育者、数据经纪人和遗物策展人的专业加工尚未实现；对应普通商品可以交易，基础保鲜与收藏可以使用。

## 美术与交付门禁

基础素材固定为 36 件商品、10 位人物、16 件工具耗材设施和 4 幅场景/结局，共 66 项。其中 64 项逐项通过 AI 图像工具生成；电子备件（`electronic-parts`）和绝缘材料（`insulation`）经用户授权分别采用原创绘制插画。发布图片位于 `public/art/`，提示词、绘制源文件与生成失败历史在资产清单登记。

`cyber:validate` 要求 64 项为 `generated`，仅上述两个 ID 允许 `original-drawn`，并核对原创绘制来源及保留的失败历史。全部 66 项检查唯一 ID 与路径、大小写、文件数量、重复图片及 WebP 容器、帧头、尺寸、透明通道和哈希。旧整张店铺图 `scene-shop` 和维修台图 `scene-workbench` 已明确归档，并保留原图或经过哈希核对的发布副本；其余资源要求真实内容引用。

新增分层场景资源在 [scenery-manifest.json](scenery-manifest.json) 独立登记，当前为 6 项、640,618 字节，包含街景、材质、终端、焊台、工作灯与零件抽屉。清单保留逐项生成提示词、原始 PNG、发布 WebP 与双方哈希。`validate-scenery.mjs` 从场景代码确定实际引用，并校验图片、原始素材和清单一致；整站检查要求全部发布图片与源文件逐字节相同。浏览器另行检查实际解码、视觉、触控、音频及完整游玩流程。

功能分支 CI 只验证，正式部署限定 `main`。代码、截图或素材数量的单项通过不等于全部验收完成。实际命令、截图、流程耗时和限制见[验收记录](docs/verification.md)。
